    A plan is a directory whose index.md is both plan and run artifact

    acceptednot accepted

    A plan lives in plans/{slug}/; index.md is the plan document and the machine's artifact at once, and run sidecars sit beside it — no separate plan.md and no _runs/ workdir.

    Context§

    Plans were flat files plans/{slug}.md. The groom playbook needed a run workdir and a machine artifact. It first used a workdir-local run.md under _runs/ whose edge hooks stamped the plan file, then a plan directory with two documents: plan.md (the executable plan) and index.md (the machine artifact and evolving run document). The skill-versus-playbook measurements found the dual artifact a root cause of the playbook's cost: content authored twice, 21 Edits, late singleton edits at 130–157k context. Making index.md the only document cut the edits from 21 to 2.

    Decision§

    A plan is the directory plans/{slug}/, which is also the run workdir. Its index.md is both the plan document and the machine's artifact. Run sidecars sit beside it: request.md (the framing brief), draft.md (the one-file plan draft before the split, adr/0030; there is no research-web step), clarifications.md, and the milestone directories. The discovery shape is the core.plans.glob config key. Flat plan files are converted by the migration 001_vault_layout.

    Directory with one index.md§

    chosencomplexity: mediumreversibility: low

    One document; sidecars beside it

    The plan document carries the run status; everything else the run writes is a sidecar.

    • Pros: one file to author and to read; the run resumes from the plan itself; groom and develop continue on the same file.
    • Cons: every plan consumer had to change from the flat glob; a migration for existing vaults.
    • Complexity: medium.
    • Reversibility: low.

    Flat plan file§

    rejectedcomplexity: lowreversibility: medium

    No home for run sidecars

    plans/{slug}.md.

    • Pros: simplest layout.
    • Cons: research, briefs and milestone files have nowhere to live beside it.
    • Complexity: low.
    • Reversibility: medium.

    Directory with plan.md and index.md§

    rejectedcomplexity: mediumreversibility: high

    Content authored twice

    The executable plan and the run document as two files.

    • Pros: the plan stays free of run bookkeeping.
    • Cons: measured: content authored twice and 21 Edits against 2.
    • Complexity: medium.
    • Reversibility: high.

    A separate runs workdir§

    rejectedcomplexity: mediumreversibility: high

    Run and plan split; hooks stamp across

    A run.md in a separate workdir; hooks stamp the plan file by path.

    • Pros: the plan file stays untouched by the procedure.
    • Cons: two locations per run; a subgraph had to dissolve to make it work.
    • Complexity: medium.
    • Reversibility: high.

    Consequences§

    • index.md's ## Milestones table and the plan's sp are generated from the milestone files, not hand-kept.
    • Plans groomed before this layout need the migration before develop can read them.

# Same rule numbers in the core and project tiers

## Question

Is a check enough, or should numbers be unique across tiers?

## Context

rule/0030 and rule/0031 exist in both tiers with different meanings (core: values in play and corrections logged; project: prompt rules earn their place and judgement on Opus). A ref without a namespace means its own tier, so the link is valid but easy to misread; adr/0024 had pointed at the core rule without the prefix.

## Proposal

Leave numbering per tier as it is; the namespace prefix is the disambiguation, and specs check could flag a cross-tier link written without one. Alternative: the project tier skips numbers the core uses.

# Develop stop points and run monitoring: core or userland?

## Question

Is a stop between groups core, and monitoring userland?

## Context

Source: [lightspace-android feedback](../notes/20261018-lightspace-android-feedback.md), points 10 and 11.

There is no "pause after group N" control, and a running develop does not re-read rules or config changed mid-run, so the manager SIGTERMed it and the run was recorded as `failed` (exit 143). Monitoring is DIY: a run monitor re-armed every 30 min, an SP report script and a session cron; the suggestions are `booping status --sp` per milestone, a run event stream and a run ETA.

## Proposal

Per value/0017, monitoring, ETA and event streams are userland on top of the run records. A clean stop between groups is development control and belongs in the core: develop checks for a stop request between groups and ends as a stop, not a failure.

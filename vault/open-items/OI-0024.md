# Rules targeted at develop or a worker never reach groom

## Question

Should groom see develop- and worker-targeted rules?

## Context

Source: lightspace-android feedback, point 8 (private note, not published).

Groom wrote tasks and ACs that contradict accepted rules: a vault edit inside a worker milestone, constant-mirroring tests against a "no constant tests" rule. Those rules target develop or the worker, so groom never sees them.

## Proposal

Groom's draft-plan sees the briefs of every rule targeting develop, its steps and the worker agents, as a check on tasks and DoD, not as instructions. Alternative: an explicit check step.

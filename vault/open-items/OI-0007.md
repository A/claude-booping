# One review stop per playbook vs the gates the code has

## Question

Rewrite adr/0015 as proposed, or change the code?

## Context

adr/0015 says each core playbook stops for review once and develop stops only on the branch. The code has more: playbook-authoring has about 10 review gates; makemigration/survey has one; project-manager/work has a plan approval and a merge gate; develop's `fail` edge needs the user to approve the abort (develop/playbook.yaml).

## Proposal

Keep the code and rewrite adr/0015 to "one review gate per run, plus a stop before an outward or irreversible action". List the exceptions with their reasons: makemigration rewrites users' vaults, the merge is outward, the abort ends a plan without a result (value/0007 force majeure). Take playbook-authoring out of the ADR: it is an interactive authoring interview, not a plan run. Separately, the owner's branch idea from 2026-10-17 is queued as its own decision: develop asks which branch, offering the last 10 branches plus the default; it proposes the default when that is the only branch; an autonomous run decides on the same inputs; every sprint is a branch merged into the default at the end.

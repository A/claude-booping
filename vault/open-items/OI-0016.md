# project-manager merges the sprint branch locally

## Question

Is a local --no-ff merge the default you want, with a PR/MR flow as a project override?

## Context

project-manager/work merges the sprint branch into the target with `git merge --no-ff` behind a merge gate, and an autonomous run settles that gate itself. No record names it. By rule/0034 the step body is its own source, so the only open question is whether the behaviour is wanted.

## Proposal

Keep it: one sprint, one branch, merged into the default at the end, which matches your branch idea. A project that delivers through PR/MR overrides it with a project rule targeting project-manager.

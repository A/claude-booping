## Context

`booping specs site` renders specs roots to a static site. The owner wants one index of
projects with a site per project (2026-10-15), on the homelab GitLab (Free tier, Pages
enabled; `lab.pages.zorya.dev` resolves to a private LAN address, so access control is
not needed). Only projects whose vault lives in the repo have their specs there to build
from.

## Decision

- **Per project.** A project whose vault is in its repo adds a `pages` job that runs
  `booping specs site --out public` on every push to its default branch; booping ships the
  job as a template. Its Pages access is public (LAN only). The site lives at
  `lab.pages.zorya.dev/<project>`.
- **Index.** The project `lab/lab.pages.zorya.dev` serves the group's Pages root
  `lab.pages.zorya.dev`: one page listing every project's site with its one-line
  description, generated by code (`booping specs site-index`). A scheduled pipeline
  rebuilds it from the group's projects that carry the topic `booping-specs`, read through
  the GitLab API with a read-only token kept as a masked CI variable; adding a project to
  the index is setting the topic.
- GitLab-specific parts (the CI template, the API discovery) are project and tracker
  concerns; the core ships the site, the index generator and the template.

## Alternatives

| Option | Status | Complexity | Reversibility | Verdict |
|---|---|---|---|---|
| [Site per project, index by topic](#site-per-project-index-by-topic) | accepted | medium | high | Each site builds with its own repo; index needs no edits |
| [One aggregated site from the notes repo](#one-aggregated-site-from-the-notes-repo) | rejected | low | high | Couples every project to one build |

### Site per project, index by topic

Each repo builds its own site; the index only links them.

- **Pros:** a project's site updates with its own push; adding a project is a topic.
- **Cons:** the index needs an API token; projects with an external vault get no site.
- **Complexity:** medium.
- **Reversibility:** high.

### One aggregated site from the notes repo

The notes repo builds one site over every project's specs roots.

- **Pros:** one build, covers external vaults too.
- **Cons:** one failing project breaks the whole site; rebuilds on every notes change.
- **Complexity:** low.
- **Reversibility:** high.

## Consequences

- Confirmation: a push to a project with the template publishes
  `lab.pages.zorya.dev/<project>`; setting the topic adds it to `lab.pages.zorya.dev` on the
  next scheduled run.

# claude-booping — Feature index

A feature is something the plugin delivers, a capability is one thing it lets someone do —
shipped only, each line tagged with the roles it serves. Terms follow [glossary.md](glossary.md).

## NFRs

- Deterministic mechanics wherever possible, to reduce token usage — state transitions, transition hooks (frontmatter stamps, named scripts, Project Vault commits), and config-rendered values execute as code, never re-derived by the model; a transition's printed mutation report is authoritative, so the runner never re-reads frontmatter to verify it
- Token economy — every step body is fetched on demand rather than pasted into a spawn prompt, keeping a run's context proportional to the graph, not to the sum of its step bodies
- Reproducible renders — macro stubs pin config-declared macros and `--project` pins the config merge to the core and project levels, so a hermetic render repeats byte-for-byte on any machine
- Schema over prose — structured data lives once in config and renders everywhere it appears, never restated in body prose
- Obsidian-ready artifacts — every Project Vault artifact is plain markdown with YAML frontmatter
- In-band failure reporting — graph and render problems surface as STOP / Note notices in the rendered output at exit 0, never as crashes

## Not features

- `skills/` and `agents/` committed files — hand-authored thin shells that pull their bodies in at load time, not a capability of their own
- `booping-create-project` — retired; Project Vault creation is the setup playbook over config-declared scaffold trees
- the `/chat` and `/help` skills — retired; `/playbook` is the plugin's only shipped skill
- `booping build` and `booping debug-template` — removed; rendering is one runtime stage, so the build stage produced nothing, and `debug-template` was never implemented
- `playbooks/_fixtures/`, `_partials/`, `_scripts/`, `_lib/` — test fixtures and shared internals beneath the playbook features
- `scripts/eval-*.sh` and the report jq filters — eval harness plumbing beneath the eval suites feature
- CI workflow and repo tooling (`justfile` internals, uv project layout) — machinery, not delivered behavior

## The task

Every model runs the same groomed three-milestone plan from the same repo state: migrate `booping frontmatter-update`'s unit-test coverage into an e2e txtar contract corpus — port the CLI-observable behaviours as named cases (M01 core CLI, M02 list ops and macros), then delete the superseded unit file after a recorded coverage cross-check (M03). The run happens in a throwaway clone on its own branch, fully autonomously, and is scored mechanically by `bench-score` plus two independent diff reviews.

## Sprint narrative

**M01 — core CLI corpus cases (1 attempt, 12m22s, commit `fed70a8`).** The worker followed the milestone's prescribed authoring procedure: stubs first, `--txtar-update` to record contracts, then an audit of each recorded file — it caught and hand-corrected one case that had captured the wrong log-line shape. 18 cases landed covering scalar sets, all eight coercion families and the error/output contract, and it correctly pinned two behaviours the unit suite never asserted (the log line names changed keys, not pairs; a no-op set still prints its summary). The one blemish the process layer charged: a rebaseline run before any red test, scored as 1 blind rebaseline.

**M02 — list-op and macro cases (1 attempt, 10m44s, commit `76c744f`).** 12 cases: append semantics across null/absent/existing keys, idempotent second append, append-onto-scalar rejection, remove, the combined-call ordering case, stubbed macros with typed coercion, both exit-2 macro failure paths, and the real-macro gap case driving `echo` through the CLI's subprocess boundary. Two judgement calls worth naming: it reasoned that "append-only call with nothing to change" is inexpressible at the CLI (argparse requires a value for `--append`) and declined to duplicate M01's `nothing-to-do` case — a defensible read the reviewers later probed; and it authored by probing the live CLI rather than the prescribed `--txtar-update` procedure. It also overstepped once on process: it hand-set the milestone file's machine-owned `status:`, which the runner reverted and re-took through the state machine.

**M03 — delete superseded units (1 attempt, 17m16s, commit `f958b27`).** The strongest showing: the coverage cross-check mapped all 58 collected unit tests/parametrizations, surfaced five CLI-observable behaviours M01/M02 had never ported, and — invoking the plan's own "delete only once covered" decision — closed them with five new rebaselined cases before deleting the unit file. Drop rationales were recorded for the five tests deliberately not ported. The worker itself flagged the five extra cases as a scope addition beyond the milestone's literal task rows; they sit inside the scope allowlist and made the deletion honest.

## The task

Every model in this benchmark gets the same groomed three-milestone plan from the same commit: port a Python unit test suite for the `frontmatter-update` CLI into the repo's txtar-based e2e corpus, write a row-by-row cross-check proving each unit test's behaviour landed somewhere in the corpus, then delete the superseded unit file. The question is whether the model can prove equivalence before destroying the thing it replaced.

## Sprint narrative

One pi session, no template, no sub-agents, no validator. All three milestones in a single attempt over 32m52s and 99 tool calls — the longest run in the matrix, at the lowest reasoning tier.

**M01 — core CLI cases.** Nineteen cases: the scalar set family, every coercion family including the partly-numeric boundary and the eight syntax-sensitive values in one call, the output contract, and the gap case split into two.

That split is the run's best work. It wrote `newline-bearing-value-round-trips`, injecting a genuine newline through a `macro_stubs` entry because argv cannot carry one, and `tab-bearing-value-round-trips`, passing a literal `0x09` byte in argv because argv *can* carry that. Both assert the round trip in expected file bytes. The immediately preceding run, at `high` effort, asserted that a newline could not be delivered at all and ticked its DoD box over half a contract.

**M02 — list ops and macros.** Twelve cases covering every list operation, the idempotency pair, the scalar-append rejection with the file asserted untouched, four stubbed-macro cases, and a real-execution case whose fixture declares `core.macros.echo` as a genuine argv command with no stub anywhere in the fixture or in `conftest.py`.

**M03 — cross-check and deletion.** The audit surfaced four CLI-observable behaviours the corpus was missing and the model added all four as cases rather than writing them off with a rationale — including one nobody else in the matrix wrote: a `.booping` marker carrying only `project_name:` resolving the vault to the home directory and landing the log line there. Then 58 rows, the unit file deleted, the sweep clean.

Thirty-five cases — the largest corpus in the matrix. Exact-name recall was **12/34**, also the highest exact figure here, and the mapping judge lifted it to **33/34 mapped**, tying the best.

Only **`malformed-append-pair-is-rejected`** is unmapped, unported for the seventh consecutive fp8 run.

Two orphans, both real contracts: the tab case (the etalon fuses both halves into one name, so only one of the two can claim it) and the home-vault marker-resolution case, which no etalon name covers and no other run in the matrix wrote.

One mapping is partial: `other-keys-comments-and-body-survive-the-set` covers the keys and body byte-for-byte, but no fixture on this branch carries a YAML comment, so the comment clause is unasserted. That is also one of the review findings.

## Review

**fable:medium — 4.0/5** (correctness 4, test quality 4, code quality 5, scope discipline 5), all 58 cross-check rows opened.
**codex — 2.0/5** (correctness 2, test quality 2, code quality 4, scope discipline 5), 15 rows sampled.

Mean **3.0**.

The reviewers agree on every fact and differ only on severity, which is the informative part. Both found the six thin error cases. Codex grades them `critical`; fable grades them `medium`, and its reason is one only a careful read yields: it checked whether any of those cases *claims* the untouched-file contract in its description, and none does. On the first `medium` run and the second `high` run, the equivalent cases stated "fails before anything is written" while asserting nothing about writes — a false claim ticked as done. Here the contract is merely unasserted. Identical metric penalty, materially different defect, and worth separating when reading the four-channel column across this matrix.

Fable's two majors are the matrix's signature failure again — a cross-check row citing a case adjacent to the contract rather than one asserting it. The retired-token rows cite a case carrying `@lead` where the units guarded `@head` and `@now`; the remove-and-empty row cites two cases while the deleted unit also asserted a YAML comment survives, and no fixture on this branch carries a comment. Four of the eight runs have now made an over-claim of this exact shape.

Against that sits the result both reviewers independently confirmed: **the newline/tab contract is fully covered**, the newline through a stubbed macro and the tab as a literal argv byte, each asserted in expected file bytes rather than diffed. Fable checked the tab with `cat -A` and the newline against the fixture's YAML escaping, and separately confirmed the real-macro case genuinely crosses the subprocess boundary.

This is also the first run where codex met its briefing in full — correct scale, both mandated findings filed, after four runs of clean sweeps or gaps logged only in passing. Its sample remains 15 rows against fable's 58.

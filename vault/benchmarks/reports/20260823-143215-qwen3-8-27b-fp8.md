## The task

Every model in this benchmark gets the same groomed three-milestone plan from the same commit: port a Python unit test suite for the `frontmatter-update` CLI into the repo's txtar-based e2e corpus, write a row-by-row cross-check proving each unit test's behaviour landed somewhere in the corpus, then delete the superseded unit file. It is a migration, not a feature — the question is whether the model can prove equivalence before destroying the thing it replaced.

## Sprint narrative

The whole plan went to one pi session with no template, no sub-agents and no validator. All three milestones landed in a single attempt over 23m55s and 92 tool calls — the slowest of the three efforts so far, and the most thorough.

**M01 — core CLI cases.** Twenty cases, the largest first milestone in the matrix. Beyond the expected scalar sets, coercion families and error paths, it wrote two cases that neither sibling run produced: `partly-numeric-string-stays-plain`, pinning that `summary=23 things` lands unquoted at the numeric-coercion boundary, and `literal-values-pass-through-untouched`, feeding the retired `@head` and `@now` tokens and asserting they are not interpolated. Both matter — see **Corpus quality**. It solved the newline obstacle a third distinct way, delivering the value through a `printf` fixture macro rather than arguing argv cannot carry a newline or routing it through a stub.

**M02 — list ops and macros.** Thirteen cases. Alongside the standard list operations and the four macro cases, it added `append-only-call-with-nothing-to-change-exits-1` — the nothing-to-do rejection when the plan already holds an appendable list, mirroring a unit-suite pair. The real-execution gap case declares a genuine `["echo", "1"]` argv macro whose output cannot arrive without the subprocess actually running.

**M03 — cross-check and deletion.** Fifty-eight rows, every collected test mapped to a named case or a recorded drop rationale, no TODO rows. Then the 572-line unit file deleted, and a stale-reference sweep that also caught a leftover `__pycache__` artifact.

The behaviour worth recording is what it did with two case descriptions. Having recorded the actual bytes, it found that the log line names the plan and the changed **key** only (`plan.md status`, not `status=in-progress`), and that the no-seconds date form lands unquoted because it does not resolve as a YAML timestamp. It corrected both descriptions to match what the CLI does rather than what the plan assumed. That is the opposite of the failure mode this benchmark is built to catch.

## Corpus quality

Thirty-four cases, the largest corpus in the matrix. Exact-name recall was **10/34**, lifted by the mapping judge to **31/34 mapped**, with three orphans — cases carrying real contracts that no etalon name covers.

What distinguishes this run is not the recall figure, which sits level with the `low` run, but *which* behaviours it covered. Two contracts that its siblings got wrong are pinned here properly:

- **`partly-numeric-value-stays-a-plain-string`** — the `medium` run has no case for this and its cross-check claimed coverage against a case setting `status=in-progress`. This run's case sets `summary=23 things` and asserts it lands unquoted in both the diff and the expected bytes. Verified directly: `grep -l '23 things'` over the corpus returns exactly that case.
- **The retired `@head` / `@now` tokens** — flagged by the reviewer as unexercised in both the `low` and `medium` runs. This run feeds them as values and asserts they land as literal strings.

Three orphans, all genuine: `ambiguous-string-gets-single-quoted` (the colon and padding half of the quoting set), `append-only-call-with-nothing-to-change-exits-1`, and `literal-values-pass-through-untouched`.

Three etalon names went unclaimed. One is the run's real gap, **`malformed-append-pair-is-rejected`** — no case anywhere feeds a malformed argument to `--append`, confirmed by inspecting every `--append` invocation in the corpus. The other two are covered without a named home: `summary-goes-to-stderr-not-stdout` is asserted by every case's exact stdout and stderr sections, and `value-may-contain-equals-signs` by `sets-multiple-keys-in-one-call`'s `'goal=a = b'`.

Rigour is the best in the matrix: **33 of 34 cases assert all four channels (97.1%)**, against 78.8% for the `medium` run, and a wildcard ratio of 0.0017 — one wildcarded line in 602.

## Mutation kills

**15/15 killed, 100%.** The fourth consecutive fp8 run to clear the frozen set.

As with every run in this matrix, the kill rate says less than it appears to. The frozen set carries no patch that only a malformed-`--append` case would catch, so the mutation layer is silent on this run's one real gap — exactly as it was silent on the `medium` run's much more serious one. A model can post 100% here with a corpus missing a contract entirely; mutation score measures whether the cases that exist bite, not whether the cases that should exist do.

## Review

**fable:medium — 4.5/5** (correctness 4, test quality 4, code quality 5, scope discipline 5), all 58 cross-check rows checked against both the cited cases and the deleted unit file recovered from the baseline.
**codex — 5.0/5** (all sub-grades 5), 58 rows read, 15 cases opened, no findings returned.

Mean **4.75** — the highest in the fp8 matrix.

Fable's verification is the substantive one: every mapped row's case genuinely asserts what the row claims, and all 26 unit methods (58 with parametrizations) are accounted for by a case or an honest drop rationale. It confirmed all three drop rationales independently, including that the e2e conftest remaps `HOME` and `XDG_CONFIG_HOME`, which makes the real-home unit test moot by construction — the same rationale it rejected as *wrong* on the `medium` run, where the row claimed sandbox isolation asserted something. Here the reasoning holds.

Its one major finding is the unported malformed-`--append` rejection, and it makes the right distinction: nothing regressed, because the deleted unit suite never covered that path either. What is missing is a contract the corpus implicitly claims to carry, not an assertion that was lost.

Its `index.md` finding is a runner artifact rather than the model's doing. The benchmark runner flips DoD checkboxes in the milestone files and takes the state transitions, but does not tick the plan index's own `## Final Verification` boxes. That is true of every run in this matrix, so it is consistent across the comparison and touches no scored column; the verification itself ran three times over — by the worker during the sprint, by `bench-score`'s gates, and by fable directly.

Codex's 5/5 is recorded with a caveat. Its positive claims all verify, including both cases it was asked to check specifically. But a clean sweep is not a complete one: the briefing stated explicitly that a never-ported behaviour must surface as a finding rather than a silent absence, and the malformed-`--append` gap — found by the mapping judge, found by fable, and confirmed here by direct inspection — is absent from its report. It is an incomplete review, not a false one, which is why the grade stands where the same reviewer's grade on the `low` run did not.

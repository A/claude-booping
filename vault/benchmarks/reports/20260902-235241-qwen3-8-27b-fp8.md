## The task

Every model runs the same groomed plan in its own throwaway clone off the same baseline: migrate `booping frontmatter-update`'s 571-line unit suite into txtar contract cases under `booping-python/e2e/cases/frontmatter-update/`, then delete the unit file once a written cross-check proves every CLI-observable behaviour it covered has a named corpus case. Three milestones — core CLI cases, list-ops and macro cases, deletion plus cross-check. The model never fixes tooling and never chooses scope; the runner drives the develop playbook and commits, the model writes the tests.

## Sprint narrative

**M01 — core CLI cases** (8m14s, 56 tool calls, commit `664cb4f`). Fifteen cases covering scalar sets, the coercion families, the error paths and the stdout/stderr split. The model followed the milestone's authoring procedure — hand-write description, fixtures and `cmd`, leave the assertion blocks empty, fill them with `--txtar-update`, read the recording back — and caught two of its own authoring mistakes that way: `summary=a: b` and a Jinja string literal both needed shell quoting in the `cmd` line because shlex was splitting the value, and its first log-case recording lacked the `[..]` timestamp wildcard the DoD requires. Those three recording rounds are also the run's only agentic deduction (see **Process profile**). It flipped the milestone's own `status:` frontmatter, which belongs to the runner's state machine, not the worker.

**M02 — list ops and macro cases** (8m54s, 53 tool calls, commit `c88a413`). Thirteen cases: eight list operations including the idempotent double append and the append-onto-a-scalar rejection, four stubbed-macro cases seeded through a top-level `macro_stubs:` mapping in the fixture config, and one real macro declared as `[echo, "1"]` argv — the only case in the corpus that proves macro execution crosses the subprocess boundary. Two protocol deviations here: the worker made its own repo commit rather than leaving the tree for the runner, and again wrote the milestone `status:` itself. Neither affects the measurement, both are worth naming.

**M03 — deletion and cross-check** (3m54s, 12 tool calls, commit `855b7bd`). A 60-row `coverage-cross-check.md` mapping every test function and parametrization of the unit file to a corpus case or a drop rationale, then the deletion and a clean stale-reference sweep. This milestone left its DoD boxes for the runner and made no commit — the correct shape, and the opposite of what the first two did. It is also where the run's real defect sits: the cross-check is where behaviours got dropped, and both reviewers went straight at it.

`just ci` was green at the end, as it was before the sprint started.

## Corpus quality

28 cases, and the model renamed nearly all of them — exact-name recall was **3/34 (8.8%)**, mapped recall **27/34 (79.4%)**. The 24-case gap is spelling alone (`append-onto-a-scalar-is-rejected` → `appending-onto-a-scalar-exits-1`, and so on), so the score rests entirely on the case-mapping judge; the mapping table sits in the run detail for audit.

Seven etalon behaviours have no branch counterpart at all:

- `=value` empty-key rejection — its own branch in the CLI with its own message
- `summary=` empty value landing as `''` — a dedicated early return, not a degenerate set
- `--append nope` malformed-append rejection — one of the three designated gap cases
- inline `# keep` comment survival through the ruamel round-trip — no fixture in the corpus carries a comment
- `23 things` staying a plain string — the partly-numeric coercion family
- the stderr/stdout split as a case of its own
- `goal=a = b` splitting on the first `=`

One further behaviour is partial: only the `a: b` mapping form of the syntax-sensitive-string family is asserted, leaving the alias, anchor, tag, `%`, backtick and padded forms unpinned. Gap cases came in at **2/3** — the newline/tab round-trip is covered (though merged into one double-quoted value, so the newline-only folded form is never seen) and the real macro is covered; malformed-append is not.

Four-channel rigour was perfect — all 28 cases assert exit, stdout, stderr and expected file bytes together — and wildcard discipline was excellent, 1 wildcarded line in 428 asserted (ratio 0.0023, well inside the full-credit band). One orphan: `an-append-only-call-with-nothing-to-do-exits-1.txtar` maps to no etalon name, and both reviewers found it to be a byte-identical copy of `nothing-to-do-exits-1.txtar` from the fixtures section on.

Worst first, and both reviewers named all of these independently:

1. The cross-check drops `=value` empty-key rejection as "a same-branch variant of the malformed-pair edge", but it is a separate branch with its own message, and no case sends it — so the deletion removed live coverage while the cross-check claimed it was pinned.
2. `goal=a = b` is dropped as pinned by two cases, neither of which contains a `=` in a value; the split-on-first-`=` behaviour now has no CLI-observable assertion anywhere.
3. Seven syntax-sensitive-string parametrizations are collapsed to one representative that exercises only the single-quote outcome, leaving the YAMLError path and the anchor/alias/tag guard unasserted — a regression writing `&anchor` as bare `null` would pass the suite.
4. `summary=` empty value and inline `# keep` comment survival are dropped without a rationale the source supports.
5. The cross-check maps the partly-numeric coercion test (`23 things`) onto the macro-date case (`2026-01-01 14:30`) — different value forms — yet M01's Task 1.2 DoD, "every coercion family with the recorded expected literal", is ticked.
6. `an-append-only-call-with-nothing-to-do-exits-1.txtar` duplicates another case byte for byte and asserts nothing about `--append`, which its name promises.
7. `re-setting-an-unchanged-value-prints-no-diff.txtar` seeds a fixture that already holds the value it sets, so both `cmd` lines are no-ops and the no-diff-on-second-call contract is demonstrated only for appends.

The two diverged only on scope discipline, 5 against 2: `fable` read the allowlist literally and found every file inside it with no source or runner edits, while `codex` scored the same drops as unsanctioned narrowing of a plan that asked for every CLI-observable behaviour. The pattern in one sentence: the cases this model wrote are rigorous and well-formed, but its cross-check reasoned its way out of writing several it should have written, and the deletion made those drops permanent.

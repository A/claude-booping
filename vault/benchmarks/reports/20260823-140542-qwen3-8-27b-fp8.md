## The task

Every model in this benchmark gets the same groomed three-milestone plan from the same commit: port a Python unit test suite for the `frontmatter-update` CLI into the repo's txtar-based e2e corpus, write a row-by-row cross-check proving each unit test's behaviour landed somewhere in the corpus, then delete the superseded unit file. It is a migration, not a feature — the question is whether the model can prove equivalence before destroying the thing it replaced.

## Sprint narrative

The whole plan went to one pi session with no template, no sub-agents and no validator. It finished all three milestones in a single attempt in 15m02s across 57 tool calls — the fastest run of the matrix so far, and about a quarter quicker than the `low` run that preceded it.

**M01 — core CLI cases.** Seventeen cases: scalar sets including comment-and-body survival, one case per coercion family, both quoting cases, the newline/tab gap case, three error paths, the unified-diff shape, the stderr/stdout split as its own named case, and the vault log line with a wildcarded timestamp. The newline case took a different route from the `low` run's — this model produced the newline through a stubbed macro rather than arguing that argv cannot carry one, which is the stronger solution to the same obstacle.

**M02 — list ops and macros.** Twelve cases covering appends onto null, absent and existing keys, idempotency, append-onto-scalar rejection, removal, the combined call, and the four macro cases. The real-execution gap case declares `echo 1` as a genuine argv macro and asserts its output lands coerced to an integer. The model also recorded a genuine CLI observation the plan did not anticipate: an append that changes nothing exits 0 with no diff, while a bare call with nothing to do exits 1 — the unit suite's empty-`--append` case is not expressible at the CLI, and it wrote that reasoning into the cross-check rather than forcing a case.

**M03 — cross-check and deletion.** Same shape as the `low` run: writing the cross-check surfaced four behaviours with no named case, and it added those four before deleting anything. Then 58 cross-check rows, the unit file removed, the stale-reference sweep, and a green `just ci`.

Two process differences from the `low` run are worth recording because neither shows up in a scored column. This model **wrote its own milestone bookkeeping**, setting `status: done` directly in the milestone frontmatter — which the playbook reserves for `playbook-transition`. And it worked almost entirely through the shell: tool mix was bash 43, edit 5, write 1, against the previous run's bash 36, write 32, edit 8.

## Corpus quality

Thirty-three cases — two more than the `low` run. Exact-name recall was **9/34**, and the mapping judge lifted that to **32/34 mapped**, the best mapped recall in the matrix so far. This model's names sit closer to the etalon's contract-shaped style (`stubbed-macro-value-lands-typed`, `summary-goes-to-stderr-not-stdout` land verbatim), and it wrote a dedicated case for the diff shape, which the `low` run left to structural assertion.

Two etalon behaviours went unclaimed and one is the run's central defect: **`partly-numeric-value-stays-a-plain-string`** has no case anywhere. The cross-check nonetheless ticks it off against a case that sets `status=in-progress`. The other, **`malformed-append-pair-is-rejected`**, is unported here as in every fp8 run to date. One orphan case, `quotes-an-ambiguous-string`, duplicates a quoting contract another case carries more directly.

The rigour figure is where this run loses ground: **26 of 33 cases assert all four channels (78.8%)**, against 30 of 31 (96.8%) at `low`. That is not scattered sloppiness — see **Review**. Wildcard discipline stays excellent at 0.0021, one wildcarded line in 476.

## Mutation kills

**15/15 killed, 100%** — the third consecutive fp8 run to clear the whole frozen set. The two broad patches each fail 26 cases here. `05_yaml-1-1-quoting-dropped` is killed by two cases rather than one, because this run's newline case routes through the quoting path as well.

No survivors, so no survivor table. Worth stating plainly: a 100% kill rate is not evidence that the two unported behaviours are harmless. The frozen set contains no patch that only a partly-numeric case or a malformed-`--append` case would catch, so the mutation layer is silent exactly where this run is weakest. Mutation score and corpus completeness are measuring different things, and this run is the clearest illustration of it in the matrix.

## Review

**fable:medium — 4.0/5** (correctness 4, test quality 3, code quality 4, scope discipline 5), all 58 cross-check rows opened, 48 holding and 10 flagged.
**codex — 2.0/5** (correctness 1, test quality 2, code quality 4, scope discipline 5), 59 rows checked, all 32 cited files confirmed present, 19 rows sampled deeply.

They converge on the worst finding. The cross-check row for `test_scalar_lands_typed[partly-numeric]` cites `sets-a-key-with-a-literal-value.txtar`, whose value is `in-progress` — alphanumeric, nowhere near the numeric-coercion boundary the unit test existed to pin. Both reviewers found it independently, the mapping judge reached the same conclusion from the other direction, and a direct grep for `23 things` across the corpus returns nothing. The contract is gone and a row claims it is covered.

Fable's first finding is the one that explains the corpus figure, and it is a category defect rather than an oversight: **all seven error cases omit the `expected/` section entirely**. Each of those cases asserts that the command fails before writing anything, and not one of them looks at the file afterwards — pytest-txtar only diffs what `expected/` lists. Those seven are byte-exactly the seven cases `bench-score` counted as thin. It also means M02's DoD line claiming the append-onto-scalar case asserts resulting file bytes is ticked over a case that does not.

Three more rows (`@head`, `@now`, `@`-prefix) all cite that same literal-value case, which contains no `@` at all, so the at-sign-stays-literal contract is unexercised. Five of eight syntax-sensitive parametrizations collapse onto a case feeding only two of the eight indicator characters, under a representative-character argument the row never states. And the real-home isolation drop rationale is simply wrong — the sandbox remaps `HOME` and `XDG_CONFIG_HOME`, which isolates the run but asserts nothing.

The pattern, across both reviewers: this run's corpus is broader than the `low` run's and its cross-check is longer, but the cross-check is doing more work per row than its citations support. Where the `low` run over-claimed on one row, this one over-claims on about ten.

Codex's grade counts this run. Its grade on the `low` run was discarded for resting on a premise that verification falsified; this run's briefing warned it about that specific failure mode and required it to grep the real file before alleging a broken citation. It did, and its findings reproduce.

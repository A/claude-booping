## The task

Every model in this benchmark gets the same groomed three-milestone plan from the same commit: port a Python unit test suite for the `frontmatter-update` CLI into the repo's txtar-based e2e corpus, write a row-by-row cross-check proving each unit test's behaviour landed somewhere in the corpus, then delete the superseded unit file. The question is whether the model can prove equivalence before destroying the thing it replaced.

## Sprint narrative

One pi session, no template, no sub-agents, no validator. All three milestones in a single attempt over 25m23s and 104 tool calls.

**M01 — core CLI cases.** Eighteen cases across scalar sets, one per coercion family, and the error and output contracts. The standout is the gap case, `newline-and-tab-bearing-values-round-trip`: this model recognised that a `cmd` line can carry neither a raw tab nor a raw newline, and routed **both** through stubbed macros rather than dropping one. The tab lands as `"a\tb"`, the newline as a multi-line scalar, and both are asserted in the stdout diff, the stderr summary and the expected file. Every earlier run in this matrix delivered at most the tab half.

**M02 — list ops and macros.** Twelve cases. `real-macro-runs-as-a-subprocess` declares `core.macros.e2e_probe: ["echo", "1"]` as a genuine argv macro — no stub — so the landed value can only come from executing it. The remove case does double duty, also pinning comment preservation and the empty-set form.

**M03 — cross-check and deletion.** The cross-check surfaced four CLI-observable unit behaviours the corpus had not pinned, and this model added all four as cases *before* deleting anything: the equals-in-value split, the partly-numeric boundary, the remove-only boundary, and all eight syntax-sensitive indicator values in one case. Then 57 rows mapping every collected test, two sanctioned drop rationales, the unit file deleted, the sweep clean.

It then closed out its own bookkeeping completely — milestone statuses, DoD checkboxes, the plan index's Final Verification boxes and `status: done`. The runner took no transitions on this branch. That matters because the previous run also self-certified and got one box wrong; this one did not. See **Review**.

## Review

**fable:medium — 4.5/5** (correctness 5, test quality 4, code quality 5, scope discipline 5), all 58 cross-check rows opened against their cited cases or drop rationales.
**codex — 5.0/5** (all sub-grades 5), 58 mappings examined, 6 spot-verified, no findings returned.

Mean **4.75**, tying the `high` run for the highest in the matrix.

Both reviewers independently confirmed the headline result. Fable read the fixture config and the expected bytes; codex read the case and the stubs; both agree the newline/tab case **genuinely delivers both halves**. That is the first time in this matrix the contract has been fully met, and it was worth verifying rather than accepting, because the case's filename is an exact match for the etalon name and would have scored as covered either way.

Fable's major is the run's real defect, and it is the matrix's most persistent failure shape: three cross-check rows justify deleting the retired-token units by citing `sets-a-key-with-a-literal-value`, whose value is `in-progress` and contains no `@` at all. The spellings `@head` and `@now` appear nowhere in the corpus; the behaviour survives only incidentally through an `@lead` value in the syntax-sensitive case. Three of the five runs so far have made an over-claim of exactly this kind — cite a case adjacent to the contract rather than one that asserts it.

Fable also verified the bookkeeping this model wrote for itself, box by box, and found **every tick honest**. That is the direct counter-example to the previous run, where a self-written DoD box claimed a newline case that did not exist. Models closing out their own bookkeeping is not inherently unreliable; that run's false tick was its own failure.

Codex's 5/5 is recorded with a caveat for the third consecutive run. Its briefing named the malformed-`--append` gap explicitly and told it a never-ported behaviour must surface as a finding rather than a silent absence. It checked, found the gap, and filed no finding — logging it in its `verified:` line as "documented in mapping5.md as intentional gap", which inverts what that document records. Its corroboration of the newline case is genuine and independent; its findings list is empty where a finding was earned.

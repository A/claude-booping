## The task

Every model runs the same groomed plan in its own throwaway clone off the same baseline: migrate `booping frontmatter-update`'s 571-line unit suite into txtar contract cases under `booping-python/e2e/cases/frontmatter-update/`, then delete the unit file once a written cross-check proves every CLI-observable behaviour it covered has a named corpus case. Three milestones — core CLI cases, list-ops and macro cases, deletion plus cross-check. The model never fixes tooling and never chooses scope; the runner drives the develop playbook and commits, the model writes the tests.

## Sprint narrative

**M01 — core CLI cases** (10m27s, 73 tool calls, commit `9377897`). Twenty cases, the largest M01 of the fp8 set, and the milestone that decided this run's shape. It ported the whole syntax-sensitive-string family rather than one representative, added `empty-key-in-a-pair-is-rejected` and `value-may-contain-equals-signs` beyond the literal task lists — flagging both in its return as deliberate additions for M03's ledger — and delivered both halves of the newline/tab gap case, a raw tab landing as a double-quoted escape and a Jinja-fed newline as a folded single-quoted block. One blind `--txtar-update` round, then a review pass over all twenty recordings in which it wildcarded a raw log timestamp the recorder had frozen. In that same pass it trimmed the `stdout` section from eleven cases where it judged the file bytes to carry the assertion; that judgement is what cost the run its `four_channel` points, and both reviewers and the metric caught it independently.

**M02 — list ops and macro cases** (5m41s, 49 tool calls, commit `237c3a4`). Thirteen cases in the fastest milestone of the run: eight list operations including a remove-of-a-missing-key no-op the etalon corpus does not have, four stubbed-macro cases seeded through `macro_stubs:` in the fixture config, and the real `[echo, "1"]` argv macro. It reasoned about placement rather than duplicating — noting that the append-only nothing-to-do argv is the same as M01's existing case and leaving that case as its home. Unlike the previous run's M02, it left the tree uncommitted for the runner and did not write its own `status:`.

**M03 — deletion and cross-check** (4m04s, 16 tool calls, commit `a5aaa34`). A 46-row ledger in file order, 40 rows mapping to named cases and 6 dropped with rationales, then the deletion and a clean sweep. It is still the weakest milestone: one row claims `remove-set-and-append-apply-in-one-call.txtar` covers the empty-value write it does not, and three rows map the `@head`/`@now`/at-sign tests onto a single `a=@lead` parameter. Both reviewers went at the first of those.

`just ci` was green in the scored worktree. The very first local invocation after M03's commit exited 1 while every stage passed individually and three subsequent full runs exited 0 — a stale bytecode cache for the just-deleted test module is the likely cause; the gate `bench-score` measured is the authoritative one and it passed.

## Corpus quality

33 cases. Exact-name recall was **23/34 (67.6%)** — this model largely kept the etalon spelling, unusually for the fp8 set — and mapped recall **32/34 (94.1%)**, the judge settling only eleven names against ten branch cases.

Two etalon behaviours have no branch counterpart:

- `key=` landing as an empty string — not a gap case, simply missed, and the cross-check then claims a case covers it that does not
- `--append nope` malformed-append rejection — a designated gap case; the corpus rejects malformed positional pairs but never a malformed append argument

Gap cases came in at **2/3**. The newline/tab case is fully covered this time, both the tab-bearing and the newline-bearing value asserted as separate keys in one recording — the previous run merged them into a single double-quoted value and never showed the folded form. The real macro is covered by a genuine `echo 1` argv declared in config.

The weak layer is four-channel rigour: **22/33 (66.7%)**. Eleven cases carry no `-- stdout --` section, which the txtar runner treats as unasserted, so the unified-diff receipt goes unchecked for a third of the corpus. Wildcard discipline was excellent, 1 wildcarded line in 394 (ratio 0.0025). One orphan case, `remove-of-a-missing-key-is-a-no-op.txtar`, maps to no etalon name — extra coverage, not a defect, though its description contradicts its own recorded stderr.

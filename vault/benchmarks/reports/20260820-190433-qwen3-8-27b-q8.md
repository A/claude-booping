## The task

Every benchmarked model runs the same groomed three-milestone plan from the same repo state: migrate `booping frontmatter-update`'s unit-test coverage into a txtar e2e contract corpus — author the core CLI cases (M01), the list-op and macro cases including three gap cases with no unit counterpart (M02), then prove coverage in a cross-check table and delete the superseded unit file (M03). The sprint runs autonomously in a throwaway clone on its own branch; the branch is what gets scored.

## Sprint narrative

**M01 — core CLI cases** (1 attempt, 13m03s, `9d5b525`). The worker authored 17 cases covering scalar sets, all coercion families, error paths, diff/stderr contract and the vault log line, following the record-then-read rebaseline procedure. It surfaced two contract facts a hand-derived expectation would have missed — the log line records the key without its value, and the rebaseline runner overwrites wildcarded lines when a sibling section mismatches, so the `[..]` wildcard had to be re-applied after the first `--txtar-update` pass. That re-application is the run's single blind rebaseline, the only agentic deduction. It left the work uncommitted, so the runner made the milestone commit; DoD held first try.

**M02 — list ops and macros** (1 attempt, 7m05s, `f8281c0`). Twelve cases: the full `--append`/`--remove` family, the combined one-call case, the stubbed-macro quartet seeded through `fixtures/xdg/booping/config.yaml`, and the real-macro gap case built on a genuine `echo 1` argv macro. The worker made a defensible judgement call in mapping the plan's "append-only call with nothing to change" onto M01's existing `nothing-to-do-is-rejected.txtar` rather than duplicating it — both reviewers later flagged that mapping, since that case passes no `--append` at all. It also correctly recorded, rather than fixed, ruamel's re-indentation of existing list members on append. Committed its own work this time; DoD held first try.

**M03 — delete superseded units** (1 attempt, 7m29s, `fde9beb`). Before deleting anything the worker audited the corpus against the unit file and found three uncovered behaviours — empty key rejected, embedded `=` kept, empty value becoming `''` — authored those cases first, then wrote the 56-row cross-check with four deliberate, plan-sanctioned drops, deleted the unit module and swept for stale references. The most disciplined milestone of the run.

All review gates were auto-answered per the benchmark's autonomy rules; no retries, no feedback files, no aborts.

## Corpus quality

32 cases. Exact-name recall was 9/34 — this model names cases in its own idiom — but the case-mapping judge matched 22 more by behaviour, landing at 31/34 (91.18%) mapped recall. The three genuinely unported behaviours: a dedicated diff-header-shape case (`diff-names-the-plan-on-both-sides`), rejection of an `--append` argument lacking `=` (`malformed-append-pair-is-rejected`, also the missed gap case, 2/3), and a dedicated stderr/stdout stream-split case (`summary-goes-to-stderr-not-stdout`) — the latter two mitigated only incidentally by other cases' channel assertions. Rigour is high where it counts: 31/32 cases assert all four channels, and the wildcard ratio is 0.0019 (one wildcarded line in 527), the corpus asserting real bytes almost everywhere. One orphan case, `unchanged-value-prints-no-diff.txtar`, maps to no etalon name — extra coverage, not noise.

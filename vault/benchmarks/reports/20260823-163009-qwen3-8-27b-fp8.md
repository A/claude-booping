## The task

Every model in this benchmark gets the same groomed three-milestone plan from the same commit: port a Python unit test suite for the `frontmatter-update` CLI into the repo's txtar-based e2e corpus, write a row-by-row cross-check proving each unit test's behaviour landed somewhere in the corpus, then delete the superseded unit file. The question is whether the model can prove equivalence before destroying the thing it replaced.

## Sprint narrative

One pi session, no template, no sub-agents, no validator. All three milestones in a single attempt over 30m19s and 95 tool calls.

**M01 — core CLI cases.** Twenty cases. The scalar-set case doubles as the diff-shape case, asserting the `---` / `+++` / `@@` headers on stdout with the summary on stderr. Coercion gets one case per family, and the ambiguous-string case uses a fully date-shaped literal (`2026-08-12`) rather than the colon form — a contract no etalon name carries, and one of the more interesting choices in the matrix.

The gap case is where this run goes wrong. `tab-bearing-value-round-trips` asserts the tab half correctly, and the case body states that a newline cannot ride a single-line `cmd`. That is false, and the run immediately before it — at a *lower* effort — had already proved it false by routing a newline through a stubbed macro. The DoD box for the whole contract is ticked anyway.

**M02 — list ops and macros.** Thirteen cases. The list operations are thorough, including the remove-and-set-empty combination that also pins inline comment survival. `real-macro-executes-its-shell-command` declares a genuine argv macro whose output can only arrive by running it.

**M03 — cross-check and deletion.** Fifty-eight rows mapping every collected test, the unit file deleted, the sweep clean.

Two authoring corrections it made along the way are worth recording, because they show the model checking its own work: it quoted `summary="23 things"` after finding the unquoted form ambiguous, and swapped the ambiguous-string value away from `1.5` on discovering that coerces to a float. Both were captured by re-recording rather than hand-derived.

## Corpus quality

Thirty-three cases. Exact-name recall was **3/34**, by a wide margin the lowest in the matrix: this model names cases in its own compressed style (`coerces-boolean`, `append-onto-scalar-exits-1`) and almost nothing collides with the etalon spelling. The mapping judge lifted that to **32/34 mapped**.

That 3-to-32 gap is worth stating as a methodology point rather than a result. On this run the recall figure — worth 15 points of `code` — is very nearly a judge output rather than a script output. It is the strongest demonstration in the matrix of why the case-mapping step exists, and equally the run where a judge error would move the score most.

Two etalon behaviours unmapped: **`malformed-append-pair-is-rejected`**, unported for the seventh consecutive fp8 run, and **`diff-names-the-plan-on-both-sides`**, which is genuinely asserted inside the literal-value case but has no case of its own to claim it. One orphan, the date-shaped literal quoting case.

The **newline/tab gap is covered only partially** — tab yes, newline never — and the judge's ruling names the premise as false rather than as a limitation.

Rigour is the joint-worst in the matrix: **26 of 33 cases assert all four channels (78.8%)**, matching the first `medium` run exactly, and for exactly the same reason. Wildcard discipline stays fine at 0.0022.

## Review

**fable:medium — 3.5/5** (correctness 4, test quality 3, code quality 4, scope discipline 5), all 58 cross-check rows opened.
**codex — 4.75/5** (correctness 4, the rest 5), 10 rows content-inspected.

Mean **4.13**.

Both reviewers land on the same headline finding, and it is the sharpest instance of this matrix's recurring failure: **the DoD box claiming the newline/tab gap case captures its contract is ticked, the case delivers half of it, and the stated justification is false.** The model declared the newline undeliverable through a `cmd` line; the previous run had already delivered it through a stubbed macro at a lower effort. This is not a limit the model hit — it is one it asserted and then certified as met.

Fable's second major explains the entire corpus-rigour figure, and it was verified directly here: **all seven error cases carry zero `expected/` sections.** `missing-plan-exits-1`, `malformed-pair-exits-1`, `empty-key-pair-exits-1`, `nothing-to-do-exits-1`, `append-onto-scalar-exits-1`, `malformed-jinja-exits-2`, `unknown-macro-exits-2`. Each claims the plan file is left untouched; pytest-txtar only diffs what `expected/` lists; none of them lists it. The identical defect in the identical seven places appeared in the first `medium` run, which is why both runs post 78.8%.

Fable also found a subtler one worth keeping: `stubbed-macro-lands-typed` declares a `macro_stubs:` entry with no real macro beside it, so the deleted test's actual claim — that a stub *wins over a declared real macro* without executing it — goes unasserted. The case proves only that stubs resolve.

Codex filed the newline finding this run, which is an improvement on three consecutive clean sweeps. Three caveats travel with its grade regardless: it returned `19/20` on a scale the briefing fixed at `/5`, so the number above is its own sub-grades averaged; it content-inspected 10 rows where fable opened all 58; and its single `info` gets the run's central corpus defect backwards, calling the thin error cases "appropriate since failed commands don't produce expected file states" when asserting the untouched file is exactly the point of those cases. It also omitted the malformed-`--append` gap for the fourth run running, after a briefing naming it explicitly.

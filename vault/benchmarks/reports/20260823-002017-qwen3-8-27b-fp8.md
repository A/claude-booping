## The task

Every model runs the same groomed plan from the same commit: port the `frontmatter-update` CLI's unit test suite to the repository's txtar end-to-end corpus, then delete the superseded unit file. Three milestones — core CLI cases, list-operation and macro cases, then a coverage cross-check followed by the deletion. The model gets a green workspace and no human to ask; what it writes is scored against a frozen etalon corpus, a frozen mutation set, and two independent diff reviewers.

## Sprint narrative

The whole plan went to one pi session, so there is one attempt and one segment rather than three. The run took 22m27s across 94 tool calls with no retry, no degenerate loop, no malformed tool input, and no context death — a clean single pass.

**M01 — core CLI cases.** Twenty-one cases covering scalar sets, the coercion families, error paths, diff shape and the log line. The model followed the plan's authoring procedure rather than shortcutting it: hand-written description, fixtures and `cmd`, assertions recorded via `--txtar-update`, then read back to confirm each contract. One contract detail surfaced during that read-back and was handled correctly — the log line names the key only (`plan.md status`), not the value, which goes to the stderr summary instead.

**M02 — list ops and macro cases.** Twelve cases: the append family, removal, the combined multi-operation call, stubbed macros, macro error paths, and a genuine argv macro. The judgement call worth naming is the date-like stub: the model's first assumption was that `2026-01-01 00:00` would land as a YAML timestamp, the rebaseline showed it does not (no seconds component), and rather than force the fixture to match its assumption it corrected the case description to match the recorded bytes. That is the right direction of correction and the one most models get backwards.

**M03 — cross-check and deletion.** All 58 unit tests and parametrizations mapped to a named case, with four explicitly recorded drop rationales — two live-clock date macros, two hook-tokenising tests rehomed to `playbook_transition_test.py`, and the real-home isolation test dropped as sandbox-by-construction. Only then was the unit file deleted, with the stale-reference grep clean.

The work came back uncommitted, as the harness requires; the runner made the three commits (`92f913e` for the corpus, `911bc23` closing the plan, `2cc4955` finishing the plan bookkeeping the sprint left behind).

## Corpus quality

Thirty-three cases. Exact-name recall was **2/34**; mapped recall is **31/34 (91.18%)**.

That gap is the largest of any run so far and it is a naming artifact, not a coverage one. This model prefixed nearly every case with an article — `an-append-extends-an-existing-list` where the etalon is `append-extends-an-existing-list`, `a-boolean-value-lands-unquoted` for `boolean-value-lands-unquoted`. Twenty-nine of the thirty-two nominal misses mapped cleanly onto etalon behaviours once read.

Three etalon behaviours have no counterpart:

- **`malformed-append-pair-is-rejected`** — genuinely absent. No case passes `--append` an argument lacking `=`. Appends parse through their own call site, so the positional-pair case does not reach that path.
- **`sets-a-key-to-a-literal-value`** and **`summary-goes-to-stderr-not-stdout`** — both asserted inside `setting-a-key-prints-a-diff-and-a-summary`, which is already claimed for the diff-shape etalon. Consolidation under the one-branch-case-per-etalon rule, not lost coverage.

Four-channel rigour is **32/33 (96.97%)** — all but one case asserts exit code, stdout, stderr and resulting file bytes together. Wildcard discipline is near-perfect: **1 wildcarded line of 590 asserted** (ratio 0.0017), the `[..]` timestamp in the log case, which is the one place a wildcard is correct.

One orphan case adds coverage with no etalon peer: `an-at-sign-value-is-a-literal`, which pins that an `@`-prefixed value is a literal rather than an interpolated token.

## Mutation kills

**15/15 killed (100%).** No survivors. Every frozen defect — dropped coercion for each scalar type, lost YAML 1.1 quoting, empty-value-becomes-null, first-equals split lost, empty key accepted, macro left unrendered, macro error exit code changed, malformed pair exit code changed, removal made a no-op, diff suppressed, summary moved to stdout, log line dropped — was caught by at least one case.

Worth noting against the corpus section: the one unported behaviour, the malformed `--append` pair, has no mutant in the frozen set, so the missing case costs nothing here. A perfect kill rate and an incomplete corpus are consistent — the mutation set measures what the corpus catches, not what it omits.

## Review

| reviewer | grade | sub-grades |

| fable:medium | 4.5 / 5 | correctness 5, test quality 4.5, code quality 5, scope discipline 4.5 |
| codex | 2.5 / 5 | correctness 2, test quality 4, code quality 4.5, scope discipline 2.5 |

Both reviewers found the same single substantive defect and nothing else: **no case rejects a malformed `--append` pair**, and the unit file was deleted anyway. fable grades it one `major` against otherwise complete work. codex reads the plan's deletion gate strictly — the corpus must cover every CLI-observable behaviour before the unit file goes — and escalates the same gap into two `critical` findings, which then depress two of its four criteria.

codex's secondary point is fair and is the more useful of the two: `coverage-cross-check.md` maps unit tests to cases, so a behaviour the *etalon* has but the *unit suite* never tested cannot surface in it by construction. The cross-check cannot catch this class of gap.

Two further minor findings from fable — unchecked Final Verification boxes and milestone task rows left at `pending` — are runner-owned plan bookkeeping rather than model output, and were completed after the review in `2cc4955`.

The 4.5-to-2.5 spread is a severity disagreement about one missing case, not two reviewers seeing different work.

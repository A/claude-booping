## The task

The fixed develop-sprint benchmark: port the `frontmatter-update` unit suite into a txtar e2e corpus across three milestones — core CLI cases, list-op and macro cases, then delete the superseded unit file after a coverage cross-check — on a clean clone at baseline `a025189`, with `just ci` green at the end.

## Sprint narrative

This run deviated from the standard per-milestone protocol on purpose: the entire plan — all three milestones — was handed to a single pi invocation, labelled `all-milestones`, to see whether the model can hold a full sprint in one session without the orchestrator splitting it. It could. One attempt, 23m53s, 88 tool calls, no retries, no malformed calls, no loops, no context deaths, no freezes. The worker walked the milestones in id order, delivered 34 corpus cases (22 for M01, 12 for M02), wrote the M03 coverage cross-check mapping all 50 unit test functions, deleted the unit file, and left the tree uncommitted as briefed. The orchestrator then validated each milestone's DoD and Verify, flipped the bookkeeping and made the per-milestone commits (`6bf2455`, `6853fc4`, `5bdde2f`). The one blemish the log shows: 3 blind rebaselines — `--txtar-update` runs not preceded by a red e2e run — which is the whole agentic deduction.

## Gates

All six pass: ci, determinism, e2e, milestones (3/3 terminal), scope (40 changed paths, all in allowlist), unit_deleted (file absent, zero stale grep hits). Nothing was close.

## Corpus quality

Exact-name recall was 7/34 — this model names cases its own way — but the case-mapping judge mapped 24 more by behaviour, landing at 31/34 (91.18%), in line with sibling runs. The three unported behaviours: `diff-names-the-plan-on-both-sides` (asserted only incidentally), `empty-value-lands-as-an-empty-string` (only inside the combined case), and `malformed-append-pair-is-rejected` (not covered at all — also the missed gap case, 2/3). Four-channel rigour 30/34 (88.24%), slightly below the best siblings. Wildcard discipline is tight: 1 wildcarded of 519 asserted lines. Three orphan cases add extra coverage beyond the etalon: `leading-zero-integer-keeps-its-text`, `no-jinja-value-passes-through-literal`, `quotes-an-ambiguous-string`.

## Mutation kills

15/15 killed (100%). Every mutation family — coercion drops, quoting, empty-value, split, macro rendering and error paths, list ops, diff suppression, summary channel, log line — died to at least one named case. No survivors to tie to the unported behaviours.

## Process profile

One segment, `all-milestones`: 1 attempt, 88 tool calls (bash 41, write 34, read 10, edit 3), 0 malformed, 0 loops, 0 deaths, 0 freezes, 452 pushed lines. The agentic score is 75.0/100: full marks on attempts and tool discipline, 0/20 on rebaseline from the 3 blind `--txtar-update` runs; churn was not measured on this run's log path and was dropped from the denominator.

## Review

fable:medium graded 4.5, codex 3.5 — mean 4.0. The convergent finding, worst first: the malformed `--append` pair error path lost its only coverage when the unit file was deleted — both reviewers flagged it, and it matches the missed gap case. Codex additionally judged the cross-check's comment-preservation row wrong (the `combined-pairs-removals-and-appends` fixture carries no comment, so that contract is genuinely untested — fable saw the same hole in `preserves-other-keys-and-body`). Pattern in one sentence: the corpus is broad and mutation-tight, but a few behaviours got narrowed or folded into combined cases instead of ported one-to-one.

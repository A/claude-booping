## The task

Every model runs the same groomed plan from the same commit: port the `frontmatter-update` CLI's unit suite to the repository's txtar end-to-end corpus, then delete the superseded unit file. Three milestones — core CLI cases, list-operation and macro cases, then a coverage cross-check followed by the deletion. The model gets a green workspace and no human to ask.

## Sprint narrative

One session, 20m30s, 89 tool calls, no retry and no blind rebaseline. The fastest run so far and the cleanest on process — the interesting question is what the reduced reasoning budget cost elsewhere.

**M01 — core CLI cases.** Nineteen cases. The coercion families are all present, including the eight syntax-sensitive values in one call and the newline/tab gap case, which this run supplied through a `printf` macro on the reasoning that a `cmd` line cannot itself carry a literal newline or tab. That is a correct read of the constraint.

**M02 — list ops and macro cases.** Twelve cases: the append family with a two-call idempotency check, removal, the combined multi-operation call, the stubbed macros with both error paths asserting stderr content, and a real `["echo","1"]` argv macro.

**M03 — cross-check and deletion.** All 58 unit tests and parametrizations mapped to a case or a drop rationale, unit file deleted, grep clean.

Two contract subtleties were noticed and recorded rather than "fixed", which is the behaviour the plan asks for: the log line names changed *keys* and not values, and a date-like value without seconds is not a YAML timestamp so it lands plain. Both match what the medium runs found independently.

Work came back uncommitted; the runner made the commits (`9f53c3b`).

## Corpus quality

Thirty-one cases, the smallest corpus of the four FP8 runs so far. Exact-name recall **7/34**, mapped recall **30/34 (88.24%)** — below every medium run.

Four etalon behaviours have no counterpart, and the shape of the misses is the story of this tier:

- **`malformed-append-pair-is-rejected`** — genuinely absent, as in every FP8 run.
- **`diff-names-the-plan-on-both-sides`** and **`summary-goes-to-stderr-not-stdout`** — both asserted only incidentally inside `sets-a-key-with-a-literal-value`, which is claimed for the literal-value etalon.
- **`empty-value-lands-as-an-empty-string`** — asserted only inside the combined multi-operation case.

Three of the four misses are the same failure mode: **contract folding**. The run bundled several distinct behaviours into one case rather than isolating each, so the assertions exist but no case owns them. A regression in the stdout/stderr split would be caught, but only as a side effect of a case named for something else — and under the one-case-per-behaviour rule the etalon behaviour counts as unported.

**Four-channel rigour dropped to 28/31 (90.32%)**, against 96.88–97.06 across all three medium runs. Three cases assert fewer than all four channels. This is the clearest single quality difference the low tier has produced.

Wildcard discipline held: **1 line of 477** (ratio 0.0021), the log timestamp.

One orphan adds nothing: `ambiguous-string-gets-quoted` duplicates a colon-ambiguous value already exercised inside `syntax-sensitive-strings-keep-their-quotes`.

## The task

Every model in this benchmark gets the same groomed three-milestone plan from the same commit: port a Python unit test suite for the `frontmatter-update` CLI into the repo's txtar-based e2e corpus, write a row-by-row cross-check proving each unit test's behaviour landed somewhere in the corpus, then delete the superseded unit file. It is a migration, not a feature — the interesting question is not whether the model can write a test, but whether it can prove equivalence before destroying the thing it replaced.

## Sprint narrative

The whole plan went to one pi session with no template, no sub-agents and no validator — the model's own doing end to end. It finished all three milestones in a single attempt over 20m33s and 86 tool calls, and never needed a retry.

**M01 — core CLI cases.** Fifteen cases covering scalar sets, the full coercion family (int, float, bool, null, the `23 things` plain-string boundary, the YAML 1.1 `yes` case), the newline/tab round-trip, three error paths each asserting exit code and stderr together, and the vault log line with a `[..]`-wildcarded timestamp. The judgement call worth recording is the newline case: a literal newline cannot cross argv in the txtar `cmd` format, so the model pinned the contract that such a value round-trips via YAML double-quoted escaping — which is what the CLI actually does, and it said so rather than quietly weakening the assertion.

**M02 — list ops and macros.** Twelve cases: appends onto null, absent and existing keys, idempotent double-append via two sequential `cmd` lines, append-onto-scalar rejection, removal, the combined call pinning the summary order, stubbed macro resolution landing typed, and both macro error paths at exit 2 with stderr content. The gap case here is the one that matters — a genuine `echo 1` argv macro declared in fixture config, executed across the subprocess boundary, its real output asserted in the resulting frontmatter. Nothing about that case can pass without the macro actually running.

**M03 — cross-check and deletion.** The model did the honest thing here: writing the cross-check surfaced four CLI-observable behaviours its own M01/M02 corpus had not pinned, and rather than paper over them it added four more cases (equals-in-value, empty-key rejection, empty-value-as-empty-string, and all eight syntax-sensitive spellings in one call) before deleting anything. Then 57 cross-check rows, then the unit file removed, then the stale-reference sweep. Final verification: 31 e2e cases green with no rebaseline, 144 unit tests green without the deleted file, grep clean, `just ci` exit 0.

The blemish is not in the code — it is in the process, and it cost the run 25 agentic points. See **Process profile**.

## Corpus quality

Thirty-one cases. Exact-name recall was **8/34** — the model named almost nothing the way the etalon does, preferring outcome-shaped names (`coerces-a-boolean`, `malformed-pair-exits-1`) over the etalon's contract-shaped ones. The case-mapping judge mapped 23 of those onto etalon names by behaviour, giving **31/34 mapped recall** with zero orphans: every case the model wrote earns its place against some etalon contract.

Three etalon behaviours are unclaimed. One is a real hole: **`malformed-append-pair-is-rejected`** — no case anywhere feeds a malformed argument to `--append`, so that parse path is unexercised, and both reviewers found it independently. The other two, `diff-names-the-plan-on-both-sides` and `summary-goes-to-stderr-not-stdout`, are covered without a named home: every success case's txtar sections assert the diff headers and the stdout/stderr split structurally, so the behaviour is pinned even though no case is dedicated to it.

Rigour is high where it counts: 30 of 31 cases assert all four channels (exit, stdout, stderr, resulting file), and the wildcard ratio is **0.0022** — one wildcarded line in 454, the log timestamp, which cannot be asserted literally.

## Mutation kills

**15/15 killed, 100%.** Every frozen patch died, and most died several times over — the two broadest, `13_diff-suppressed-on-change` and `14_summary-to-stdout`, each fail 24 separate cases, which is what four-channel discipline buys you. The narrow patches died to exactly the case you would want: bool coercion to `coerces-a-boolean`, first-equals-split to `value-containing-an-equals-sign-keeps-it`, the log line to `logs-one-line-when-a-vault-is-attached`.

No survivors, so there is no survivor table and nothing to tie back to the unported `--append` behaviour — the frozen mutation set does not contain a patch that only that case would catch. The 100% kill rate is a real result, but it is not evidence that the one unported behaviour is harmless; it is evidence that the mutation set does not probe there.

Every agentic deduction in this run comes from one place. Attempts scored a clean 30/30 — one pass, no retries. Tool discipline scored a clean 30/30 — no malformed inputs, no degenerate loops, no context deaths, no freezes. **Rebaseline scored 0 of 20**: the model invoked `--txtar-update` twice without first running the corpus red, which is the benchmark's definition of a blind rebaseline — regenerating expected output rather than checking the output against an expectation. That single behaviour is the entire 25-point gap between this run's 75.0 and the 100.0 that earlier fp8 low runs posted.

It is worth being precise about the severity. The final state is not compromised: the determinism gate confirms the committed corpus passes without rebaselining, so the model did not ship self-agreeing tests. What the two blind rebaselines show is a working habit — reaching for regeneration during development instead of reading a failure — and the metric penalises the habit, not the artifact. Write calls (32) outnumbering read calls (10) by better than three to one points the same way.

## Review

**fable:medium — 4.0/5** (correctness 4, test quality 4, code quality 4, scope discipline 5), having opened all 57 cross-check rows against their cited cases.

Worst first: one row justifying the deletion **miscites its evidence** — the `test_file_target_with_quoted_macro_expression` row points at a test whose hook is the plain literal `seen=recorded` and never carries a quoted macro expression, so the row's justification is false, though the behaviour survives because a neighbouring row's cited test happens to cover that path. Then two medium findings: the `@head`/`@now` retired-token rows cite a case containing `@lead` and no case feeds the actual retired spellings, so a reintroduced special case for those tokens would pass the corpus; and the unported `--append` malformed-pair rejection. One minor: the real-home guard row delegates to the sandbox's HOME mapping, which isolates but asserts nothing, so that unit's assertion is genuinely lost — stated honestly in the row. Two info items record defensible declared trades.

**codex — no usable grade.** It returned 2/5, but the grade rests on a claim this run verified false: that 21–23 cross-check rows cite etalon case names with no file behind them. Every one of the 30 distinct `.txtar` names the cross-check cites exists on the branch, and the two names codex quoted as cited do not appear in the file at all — it read the case-mapping table's etalon column as the cross-check's citations. Its scope and txtar-validity sweeps are sound and agree with fable; only the grade is discarded, and per method it is neither re-run nor replaced with fable's.

The pattern across both reviewers, once the reading error is set aside: the cross-check is structurally honest and overwhelmingly accurate — 51 of 57 rows exercise exactly what they claim — with three soft spots that are all failures of *proof* rather than of coverage. The model proved slightly more than it had.

## The task

The benchmark hands every model the same groomed three-milestone plan at the same repo state: port `booping frontmatter-update`'s 571 lines of unit tests into a txtar contract corpus under `booping-python/e2e/cases/frontmatter-update/`, add the gap cases the units never had, then cross-check the coverage and delete the unit file wholesale. The model gets its own throwaway clone and its own branch, answers no questions, and is scored on the branch it leaves behind.

## Sprint narrative

Third of three back-to-back runs at identical settings, same all-at-once shape: all three milestones in one pi session, one segment, one attempt. 15m55s across 86 tool calls, and a noticeably different tool mix from its siblings — 27 bash against 20 read, where the 12:17 run read 8 times and ran bash 34 times. This session spent more of its budget reading the CLI and less of it probing by execution, and it is the run with the highest recall.

M01 produced 20 cases: the scalar sets, the coercion families, the eight-value syntax-sensitive battery, the error paths each pairing exit code with stderr message and an untouched file, and separate dedicated cases for the two output-contract behaviours — `prints-a-unified-diff-on-stdout` and `summary-goes-to-stderr` — that the 12:40 run folded into one. M02 added 13 across the list ops and both macro paths, including a genuine `echo 1` argv macro. M03 wrote the cross-check over all 47 unit tests and parametrizations with two recorded drops, and deleted the unit file. 33 cases, every `## Verify` green with no case rewritten on a clean run, and `just ci` green at the end.

The one judgement call is also the run's main defect. For the newline-and-tab gap case the session wrote only the tab half, recording in the case description that a newline cannot be expressed in a one-line `cmd`. Both reviewers independently checked that premise and found it false — the value passes through Jinja in `interpolate`, so `'lined={{ "x\ny" }}'` carries a real newline through `shlex.split`. The session reasoned about the constraint instead of testing it, and dropped half a behaviour the plan named.

The process record is otherwise spotless: no retry, no feedback file, no malformed tool input, no loop, no context death, no blind rebaseline. The runner validated the tree, confirmed `just ci` green, and made the commit; the vault bookkeeping is the runner's.

## Gates

All six pass: `just ci` exit 0, a `--txtar-update` rerun that rewrote nothing, `just e2e` green, 3/3 milestones terminal, 39 changed paths all inside the allowlist, and the unit file gone with a clean stale-reference grep.

## Corpus quality

Exact-name recall was **3/34**; mapped, **32/34** (94.12%) — the highest of the three runs. Gap coverage is **2/3**. Two etalon behaviours went unported:

- `malformed-append-pair-is-rejected` — the uncovered gap case, missed by all three runs. `--append nope` exits 1 through the same `parse_pairs` call and no case reaches it.
- `partly-numeric-value-stays-a-plain-string` — the behaviour is asserted, but only as a third pair inside `sets-a-key-with-a-literal-value.txtar`, whose own description names the bare-value and equals-sign behaviours instead. Coverage a case does not claim is coverage the next edit silently trims.

The newline/tab gap case counts as covered on the tab half alone; the newline half is not written anywhere. Rigour is high: **32/33** cases assert all four channels, and the wildcard ratio is **0.0019** — one wildcarded line in 538, the log timestamp. One orphan case, `quotes-date-like-string`, answers the plan's "ambiguous string gets quoted" task rather than exceeding scope.

## Mutation kills

**15/15 killed** — a clean sweep, no survivors, matching both sibling runs. Coercion drops, quoting drops, the diff suppression, the summary redirection and the dropped log line all died. The mutation set does not attack either unported behaviour, which is why a perfect kill rate and two coverage holes coexist here.

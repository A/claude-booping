Every model gets the same groomed three-milestone plan from the same repo state: migrate `booping frontmatter-update`'s unit tests into a txtar e2e contract corpus — write the core CLI cases, write the list-op and macro cases including a real-macro subprocess proof, then delete the superseded unit file behind a recorded coverage cross-check. The worker delivered 19 cases covering scalar sets, all coercion families, the error paths, the diff/stderr output contract and the vault log line, and followed the plan's authoring procedure as written: skeletons first, then `--txtar-update` to record the contract, then a read-back. **M03 — delete superseded units** (1 attempt, 29m16s, commit `407194a`). The worker enumerated all 58 unit-test instances by pytest node id, mapped 53 to named corpus cases and recorded drop rationales for 5, wrote the cross-check table, deleted the unit file, swept for stale references and ran the full `just ci` — the longest milestone by far, most of it spent grounding mappings against the real CLI. The cross-check is complete in form; the review pass below shows two of its rows map to behaviourally different cases.

The three behaviours genuinely unported: an empty value landing as an empty string, a malformed `--append` pair being rejected (one of the three gap cases, so gaps score 2/3), and a partly-numeric value staying a plain string. Rigour is high where cases exist: 30/31 cases assert all four channels, and wildcard discipline is the best kind — 1 wildcarded line in 528, the log timestamp.

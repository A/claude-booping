## The task

Every model in this benchmark gets the same groomed three-milestone plan from the same commit: port a Python unit test suite for the `frontmatter-update` CLI into the repo's txtar-based e2e corpus, write a row-by-row cross-check proving each unit test's behaviour landed somewhere in the corpus, then delete the superseded unit file. The question is whether the model can prove equivalence before destroying the thing it replaced.

## Sprint narrative

One pi session, no template, no sub-agents, no validator. All three milestones in a single attempt over 30m46s and 104 tool calls — the most tool calls and the longest wall clock of the current batch, at the *lowest* reasoning tier.

**M01 — core CLI cases.** Twenty-two cases, the largest first milestone in the matrix. It covered contracts its `low` and `medium` siblings left unclaimed: `a-partly-numeric-string-stays-plain` for the numeric-coercion boundary, `at-sign-and-space-value-passes-through-untouched` for the retired token behaviour, and a dedicated `success-summary-goes-to-stderr` case taking the stream split as its own subject rather than leaving it to structural assertion.

**M02 — list ops and macros.** Twelve cases across the list operations and the four macro paths, with `real-macro-executes-through-the-cli` declaring `["echo", "1"]` as a genuine argv macro whose output cannot arrive without the subprocess running.

**M03 — cross-check and deletion.** A 58-row cross-check matching the 58 collected tests exactly, then the unit file deleted, then the sweep.

The method it described is worth recording, because it is the most disciplined authoring loop any run in this matrix has stated: hand-write the description, fixtures and `cmd`; fill the assertions with `--txtar-update`; then **read each rewritten file back to confirm the recorded contract**. That read-back caught one of its own wrong descriptions — the date-like stub case lands plain, not quoted.

That loop is also why this run scores where it does on process. Using `--txtar-update` during authoring is not what the rebaseline metric penalises; regenerating past a red test without reading it is. This run did the former and scored zero blind rebaselines.

## Corpus quality

Thirty-four cases. Exact-name recall was **7/34** — the lowest exact figure in the matrix, since this model names cases in its own descriptive style (`a-value-containing-equals-is-kept-whole`, `the-yaml-1-1-yes-word-stays-a-string`). The mapping judge lifted that to **33/34 mapped**, the highest mapped recall of any fp8 run. The gap between 7 and 33 is the clearest demonstration in the matrix of why the exact-name figure alone would be worthless: this run has the best behavioural coverage and the worst spelling agreement.

Only one etalon behaviour is unmapped: **`malformed-append-pair-is-rejected`** — no case feeds `--append` a token lacking `=`. Fifth consecutive fp8 run to leave it.

Two mappings are partial, and one of them is this run's real defect:

- **`newline-and-tab-bearing-values-round-trip`** — the tab half is asserted exactly, the newline half does not exist anywhere in the corpus. M01's DoD box claiming this case done is ticked anyway. See **Review**.
- **`other-keys-comments-and-body-survive-the-set`** — sibling keys and the body survive byte-for-byte, but no fixture on this branch carries a YAML comment, so comment survival is unasserted.

One orphan, `at-sign-and-space-value-passes-through-untouched`, guarding retired-token behaviour no etalon name carries.

Rigour is high: **33 of 34 cases assert all four channels (97.1%)**, wildcard ratio 0.0019.

## Review

**fable:medium — 4.0/5** (correctness 4, test quality 4, code quality 5, scope discipline 4), all 58 cross-check rows opened, 54 holding exactly.
**codex — 2.0/5** (correctness 2, test quality 4, code quality 5, scope discipline 5), 25 cited cases checked, 8 spot-checked deeply.

Mean **3.0**, and the spread is the widest in the matrix — but not because the reviewers disagree about the branch.

Fable's first finding is the run's genuine defect. **M01's DoD box asserting the newline/tab gap case is done is ticked, and no case in the corpus carries a newline-bearing value.** This model wrote its own milestone bookkeeping — the benchmark runner ticked nothing on this branch — so the claim is the model's own. It belongs to the same family as the `medium` run's `partly-numeric` row: a contract certified as delivered that was not. It is milder, because half the case genuinely exists and the tab round-trip is asserted byte-exactly, where the `medium` run's contract was absent outright and its citation pointed at an unrelated case.

Fable's second is a quieter loss of the same kind. The deleted unit asserted that a YAML comment survives a rewrite; no case on this branch carries a comment at all; the cross-check cites two cases for that unit and records no loss.

**Codex's two `critical` findings do not survive verification of the contract.** It graded the cross-check for omitting rows for `a-tab-bearing-value-round-trips` and `malformed-append-pair-is-rejected`. Both are registry `gap_cases` — defined as cases with no unit-test counterpart — and the deleted suite provably contains no malformed-`--append` test at all. The cross-check maps unit tests to cases, so it owes neither a row, and their absence is not the defect codex grades it as. Its underlying observations are factually correct and its spot-checks all verify; only the severities are wrong. This is a different failure from its `low`-run review, where the facts themselves were false and the grade was discarded; here the grade stands with the misreading recorded.

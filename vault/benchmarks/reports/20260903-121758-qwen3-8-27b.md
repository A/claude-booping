## The task

The benchmark hands every model the same groomed three-milestone plan at the same repo state: port `booping frontmatter-update`'s 571 lines of unit tests into a txtar contract corpus under `booping-python/e2e/cases/frontmatter-update/`, add the gap cases the units never had, then cross-check the coverage and delete the unit file wholesale. The model gets its own throwaway clone and its own branch, answers no questions, and is scored on the branch it leaves behind.

## Sprint narrative

This run took the all-at-once shape: all three milestones went to a single pi session in one delegation rather than one briefing per milestone, so the whole sprint is one log segment and one attempt. It finished in 15m40s across 82 tool calls — 34 bash, 34 write, 8 read, 6 edit — with no retry, no feedback file, no malformed tool input and no degenerate loop.

The session wrote 21 cases for M01 (scalar sets, the coercion families, the error paths, and the `.booping.log` side effect with its timestamp wildcarded), 11 for M02 (the list ops, the two macro paths including a real `echo 1` argv macro proving execution across the subprocess boundary, and the two exit-2 error cases), then in M03 added two more cases it found missing during its own cross-check, wrote `coverage-cross-check.md` mapping all 55 unit tests and parametrizations to a case or a recorded drop, and deleted `frontmatter_update_test.py`. 33 cases in total. It ran each milestone's `## Verify` as it went and finished with the full unit suite (727) and the full e2e corpus (71) green.

The one blemish in the process record: **2 blind rebaselines** — `--txtar-update` invocations run without a preceding red e2e run, which is the pattern of filling an expected block by rerunning the tool rather than by reading a failure. That single signal is what separates this run from the day's other two.

The runner validated the tree, confirmed `just ci` green, and made the commit; the vault bookkeeping (milestone statuses, task rows, DoD checkboxes) is the runner's, applied after the sprint.

## Corpus quality

Exact-name recall was **2/34** — the model renamed nearly every case. After the case-mapping judge read the bodies, mapped recall is **30/34** (88.24%), and gap coverage went from 0/3 to **2/3**. The four unported behaviours:

- `diff-names-the-plan-on-both-sides` — no case targets the `---`/`+++` header naming as its own assertion; it is incidental in every diff-producing case.
- `malformed-append-pair-is-rejected` — the gap case that stayed uncovered. `--append noequals` exits 1 through the same `parse_pairs` call, and no case reaches it.
- `stubbed-macro-value-lands-typed` — the branch has exactly one stubbed-macro case and it stubs a date-shaped string, so the judge gave it to the date-shaped etalon name and left this one unmapped.
- `value-may-contain-equals-signs` — only incidental inside `literal-values-pass-through-untouched.txtar`.

Rigour is high where it was measured: **32/33** cases assert all four channels (exit, stdout, stderr, expected bytes), and the wildcard line ratio is **0.0016** — one wildcarded line in 608 asserted, and that one is the log timestamp. Three branch cases have no etalon counterpart: `long-value-wraps-and-round-trips`, `tab-in-value-lands-in-file` (the other half of the newline/tab gap case) and `unchanged-value-prints-no-diff`.

## Mutation kills

**15/15 killed** — the full frozen set, a clean sweep with no survivors. Coercion drops, quoting drops, the diff suppression, the summary-to-stdout swap and the dropped log line all died against at least one case; several died against many. On this benchmark a perfect mutation score is the strongest single evidence that the corpus is a real contract and not a set of snapshots.

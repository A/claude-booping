## The task

## Sprint narrative

**M01 — core CLI cases** (1 attempt, 22m33s, `5cd921f`). The worker wrote 18 cases covering the scalar-set family, the coercion families one case apiece, and the error and output contracts, following the milestone's own procedure: hand-write description, fixtures and `cmd`, leave the assertions empty, rebaseline, then read every rewritten file back. One judgement call worth naming: the vault-log case revealed that the log line names only the key, not the value, and the worker recorded the CLI's actual behaviour as the contract rather than "fixing" the implementation to match its expectation — the right instinct for a corpus whose whole purpose is to pin observed behaviour. The one blemish of the whole run also sits here: a single rebaseline went through without the case bodies being read back first, which is the lone agentic deduction below.

**M02 — list ops and macro cases** (1 attempt, 9m58s, `ff112ae`). Twelve cases: the seven `--append`/`--remove` behaviours, four stubbed-macro cases seeding `macro_stubs:` in the fixture's XDG config tier, and the real-macro case that declares `core.macros.probe: [echo, "1"]` and proves live execution through the subprocess boundary — the frontmatter value `note: 1` cannot arrive any other way. The worker noticed that ruamel emits appended lists zero-indented and that the unknown-macro error double-quotes the offending value, and captured both as the contract instead of arguing with them. It also declined to write a duplicate case for "append-only call with nothing to change", correctly reasoning it is the same CLI path as M01's `nothing-to-do-exits-1` — a judgement the case mapping later confirmed, though it is adjacent to the one behaviour the corpus does miss.

**M03 — cross-check and deletion** (1 attempt, 12m52s, `207562e`). The worker collected the unit file with `--collect-only` to get an exact test count rather than trusting a grep, mapped all 58 collected tests to a named case or a drop rationale in `coverage-cross-check.md`, and let that exercise surface three behaviours M01 and M02 had missed — equals-signs in values, empty keys, empty values — writing a case for each before deleting anything. That ordering is what the milestone asks for and what makes the deletion safe. The unit file then went, the stale-reference sweep came back clean, and `just ci` was green end to end.

The runner auto-answered three gates, all per the guide's answer sheet: plan approval on entry, the drift check (only groom commits sit between the plan's commit and the baseline), and the branch, which was cut before the sprint began.

## Corpus quality

33 cases. Exact-name recall against the frozen etalon list was 2/34 — the branch names cases `an-integer-lands-unquoted` where the etalon says `integer-value-lands-unquoted` — so the mapping judge read the case bodies and settled it at **33/34 mapped**. The one behaviour genuinely absent is `malformed-append-pair-is-rejected`: no case feeds `--append` a pair without `=`. The corpus's only malformed-pair case passes a bare positional, which exercises a different parsing branch, and the same hole costs it one of three gap cases (the other two, newline/tab round-trip and live macro execution, are covered).

Rigour is high where it is measured: 32 of 33 cases assert all four channels — exit code, stdout, stderr and resulting file bytes — and one wildcarded line in 500 asserted lines, the timestamp in the vault-log case, which is the only thing in the corpus that cannot be pinned.

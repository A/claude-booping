## The task

Every model runs the same groomed plan from the same commit: port the `frontmatter-update` CLI's unit suite to the repository's txtar end-to-end corpus, then delete the superseded unit file. Three milestones — core CLI cases, list-operation and macro cases, then a coverage cross-check followed by the deletion. The model gets a green workspace and no human to ask.

## Sprint narrative

One session, one segment, 21m08s across 54 tool calls. No retry, no loop, no malformed input, no context death — but two blind rebaselines, which is where this run differs from the one before it.

**M01 — core CLI cases.** Twenty cases. The model followed the plan's authoring procedure — hand-write description, fixtures and `cmd`, record assertions via `--txtar-update`, read back to confirm. The one blemish worth naming is in this milestone and the model caught it itself: the rebaseline flattened the `.booping.log` case's `[..]Z:` timestamp wildcard into a concrete timestamp, which it then hand-restored. Left alone that would have made the case fail on its next run.

**M02 — list ops and macro cases.** Twelve cases: the append family, removal, a combined multi-operation call, stubbed macros, macro error paths, and a genuine `["echo","1"]` argv macro whose asserted value can only come from executing it. As in the previous run, the date-like stub was handled correctly — the no-seconds form is not a YAML timestamp, and the model verified both readers reload it as `str` before correcting its own description to match rather than bending the fixture.

**M03 — cross-check and deletion.** All 58 collected unit tests mapped to a named case or a recorded drop rationale; the 572-line unit file deleted; the stale-reference sweep clean apart from the regenerable `.pytest_cache`.

Work came back uncommitted as required; the runner made the commits (`c0eeb7d`).

## Corpus quality

Thirty-two cases. Exact-name recall **9/34**, mapped recall **31/34 (91.18%)**.

The naming is much closer to the etalon than the first FP8 run managed (9 exact against 2) — this run used bare behavioural names like `sets-a-boolean` and `malformed-pair-exits-1` rather than article-prefixed ones. The mapped total is identical, so the difference is legibility, not coverage.

Three etalon behaviours have no counterpart:

- **`malformed-append-pair-is-rejected`** — genuinely absent, the same gap as the previous run. The only `--append` failure case tests a scalar target; the malformed-pair case tests a positional pair. The append parse path is never driven.
- **`empty-value-lands-as-an-empty-string`** — asserted only inside the combined multi-operation case, so a regression there is entangled with removal and append ordering.
- **`sets-a-key-to-a-literal-value`** — no case isolates a plain literal set. The case named `sets-a-key-with-a-literal-value` actually asserts first-`=`-only splitting, and is claimed for that etalon instead.

Four-channel rigour **31/32 (96.88%)**. Wildcard discipline **1 line of 474** (ratio 0.0021) — the log timestamp, the one place a wildcard belongs.

One orphan adds coverage: `setting-an-unchanged-value-prints-no-diff`, which reaches the no-diff contract through a fixture already holding the target value — a different entry point from the two-call re-setting case.

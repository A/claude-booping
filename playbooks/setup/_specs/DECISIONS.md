- `[2026-08-04 09:57]` CORRECTION to an earlier decision recorded this run: the claim "a `jinja: true` playbook without project context is a blocking STOP" was wrong. The `_NO_CONTEXT` STOP in `booping-python/src/booping/commands/render_playbook.py` fires only when the assembled `Context` object is `None`, and the CLI always assembles one (with `project: None` outside a project). Verified: `booping render-playbook setup` renders clean with `jinja: true`, outside any project, with an empty global config. The only real rule is that bodies must not dereference `context.project`.
- `[2026-08-04 09:57]` Decision: the `setup` playbook therefore sets `jinja: true`, and its step bodies follow the core pattern used by `groom` and `playbook-authoring` — `prompt.md` carries the frontmatter plus a single `{% include "<model>.md" %}`, with the body in the model-named sibling file (`setup-booping/sonnet-5.md`, `setup-project/opus-5.md`).

Rationale: the home dir is one git repo covering every vault under it, which is what `booping vault-commit` relies on when it runs git from inside a vault.
